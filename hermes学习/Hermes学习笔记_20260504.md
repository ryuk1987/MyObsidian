## 1. WSL 连接 Windows MySQL

### 问题：网段不同无法互通

- WSL IP：`172.28.248.175`（Hyper-V NAT 网络）
- Windows 物理网卡 IP：`192.168.8.166`
- WSL 的默认网关：`172.28.240.1`（vEthernet WSL 虚拟网卡）

**结论**：WSL 和 Windows 物理网络不在同一网段，不能直接互 ping。

### 打通步骤

**① Windows 防火墙放行 MySQL 端口（CMD 管理员）**
```cmd
netsh advfirewall firewall add rule name="MySQL from WSL" dir=in action=allow protocol=tcp localport=3306
```

**② MySQL 授权 WSL 的虚拟网络 IP（CMD）**
```sql
-- 查看 WSL 在 MySQL 眼里的 IP：172.28.248.175
CREATE USER IF NOT EXISTS 'root'@'172.28.248.175' IDENTIFIED BY '123456';
GRANT ALL PRIVILEGES ON *.* TO 'root'@'172.28.248.175' WITH GRANT OPTION;
FLUSH PRIVILEGES;

-- 若 *.* 权限不够，单独授权
GRANT ALL PRIVILEGES ON ruoyi.* TO 'root'@'172.28.248.175';
FLUSH PRIVILEGES;
```

**③ WSL 侧连接**
```python
# 依赖：pymysql + cryptography
# 运行：uv run --with pymysql --with cryptography python3 <script.py>
import pymysql

conn = pymysql.connect(
    host='172.28.240.1',   # 注意：不是 192.168.8.166，而是虚拟网卡 IP
    port=3306,
    user='root',
    password='123456',
    database='ruoyi',
    charset='utf8mb4',
    connect_timeout=10
)
```

### 踩过的坑

- WSL 要连 Windows MySQL，必须用 `172.28.240.1`，不是物理网卡 IP
- MySQL 8.0 使用 `caching_sha2_password` 认证，需要 `cryptography` 包
- `GRANT ALL ON *.*` 对单个库权限可能不够，需单独授权
- 防火墙不仅拦 ICMP，还拦所有 TCP 端口

## 3. TTS 语音配置

### 问题原因
edge 模式一直失败，因为配置的语音是英文（`en-US-AriaNeural`），不适合中文回复。

### 解决方法
编辑 `~/.hermes/config.yaml`：
```yaml
tts:
  provider: edge
  edge:
    voice: zh-CN-XiaoxiaoNeural   # 改为中文语音
```

### 测试（CLI 下生成音频文件）
```python
# edge-tts 中文测试
uv run --with edge-tts python3 -c "
import asyncio
from edge_tts import Communicate
async def test():
    comm = Communicate('你好，我是 Hermes', voice='zh-CN-XiaoxiaoNeural')
    await comm.save('/tmp/test_edge.mp3')
asyncio.run(test())
```

CLI 下用 `text_to_speech` 工具生成音频文件（微信不支持自动播放语音消息）。

## 5. Profiles（多配置切换）

### 概念
同一台电脑运行多套完全独立的 Hermes 配置，互不影响。

### 目录结构
```
~/.hermes/
├── profiles/
│   ├── work/        # 独立 config.yaml、skills、memories
│   └── dev/         # 独立配置
├── default/         # 默认配置
```

### 使用
```bash
hermes --profile work    # 用 work 配置
hermes --profile dev     # 用 dev 配置
hermes --profile default # 默认配置
```

每个 profile 独立：config.yaml、skills、memories、home/（git/SSH）

## 6. SOUL.md vs Personalities vs System Prompt

### 三层关系（不冲突）

| 机制 | 位置 | 作用 | 修改方式 |
|------|------|------|---------|
| **SOUL.md** | `~/.hermes/SOUL.md` | Agent 的底层人设，**每次对话都读** | 编辑 SOUL.md 文件 |
| **Personalities** | `config.yaml` 的 `personalities` 节点 | 可切换的预设人格（pirate/kawaii/noir等） | 编辑 config.yaml |
| **System Prompt** | `config.yaml` 的 `agent.system_prompt` | 默认提示词，无 personality 激活时使用 | 编辑 config.yaml |

### 加载顺序
```
每次对话：
  SOUL.md → 底层人设（始终加载）

  若 /personality pirate 激活 → 覆盖 system_prompt
  若无 personality 激活 → 使用 agent.system_prompt
```

## 7. Nix 是什么

Linux/macOS 的包管理器（类似 apt/brew），特点是：

- **可重现构建** — 任何机器上依赖版本完全一致
- **用户级安装** — 不需要 sudo
- Hermes 用 nix 来确保环境一致

你当前用 `uv` + `venv` 管理 Python 依赖，和 nix 是同类工具，各有优劣。

## 8. Hermes 可用 Skills 路径

本地 skills 目录：`~/.hermes/skills/`

文件夹结构的 skill（如 `xhsongshu-operator/`）无法通过 `skill_view()` 自动加载，**需要直接读取 `SKILL.md` 文件**：
```python
# 用 read_file() 读取
read_file(path='~/.hermes/skills/xxx/SKILL.md')
```
